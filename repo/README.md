## 만든 방식 — AI 활용에 대해 정직하게

- **제가 한 일**: 공고를 입력·계산·판정·문서 단계로 나눠 무엇을 자동화할지 정했고, 계산 규칙(관리도 규칙, 규정상 기한, 반올림 규칙 등)의 방향을 정했습니다.
- **AI가 한 일**: 위 방향에 따라 실제 코드(상태관리, 날짜 계산, 차트, UI)를 구현했습니다.
- **검증한 방식**: 이론단수·회수율 같은 계산은 별도로 다시 계산해 도구 값과 대조했고, 그 대조값을 도구 안에 자체 검산(self-test)으로 내장해 페이지를 열 때마다 자동으로 재확인되게 했습니다. 규칙을 잘못 고치면 검산이 먼저 깨집니다.
- **AI가 하지 않는 일**: 품질 판정 확정, 배치 출하 승인, CAPA 원인 확정 — 이런 최종 판단은 어느 도구에서도 자동화하지 않았습니다. 확인이 필요한 지점을 먼저 보여주는 역할로 범위를 한정했습니다.

## 지켜야 했던 경계

- 모든 예시 데이터·규격값·회사 이름은 공개된 공고·규정을 참고했거나 학습·시연 목적의 가상 값입니다. 실제 사내 데이터가 아닙니다.
- 계산식이 필요한 부분(HPLC 이론단수, 표시기준 반올림, GMP 회수 등급별 기한 등)은 공식 규정·공정서 원문을 근거로 구현했습니다.
- 각 도구의 "제작 노트" 페이지에 실제 제 경험(LC 운용, KTL GMP 교육, SOP 작성 등)과 이번에 새로 이해를 바탕으로 구성한 부분을 구분해뒀습니다.

## 기술적으로

- 프레임워크·빌드 도구 없이 **단일 HTML 파일**로 동작합니다 (외부 CDN 의존성 없음, 인터넷 연결 없이도 실행).
- 데이터는 브라우저 메모리에만 있고 어디로도 전송되지 않습니다. 새로고침하면 예시 데이터로 초기화됩니다.
- 회사별로 실제 CI 컬러(또는 확인 가능한 범위에서 가장 가까운 값)를 사용했습니다.
